## 1. Як дані потрапляють у систему

```
Smartlead / Bison
  │  (відправляють листи)
  ▼
n8n (автоматизація)
  │  (підраховує: скільки відправлено, скільки відповідей, стрибки)
  │  (класифікує відповіді: людська/OOO/негативна)
  │  (створює ліди при кваліфікації)
  ▼
Supabase (база даних)
  │
  ├── campaign_daily_stats  — щоденна статистика по кампанії
  ├── daily_stats           — щоденна зведена статистика по клієнту
  ├── leads                 — ліди (MQL, preMQL тощо)
  └── campaigns             — кампанії (database_size = кількість проспектів)
  │
  ▼
Портал (цей сайт)
  │  читає дані, рахує метрики у браузері
  └── показує адміністратору / менеджеру / клієнту
```

**Ключовий факт:** Портал **тільки читає та відображає** дані. Жодних листів він не надсилає. Все що бачите у таблицях — вже записано зовнішніми системами.

## 2. Фільтр по часу (Timeframe) — загальні правила

Майже кожна сторінка має кнопку вибору часового діапазону. Ось що означає кожен пресет:

| Пресет | Що включає | Приклад (якщо сьогодні 27 травня 2026) |
|--------|-----------|----------------------------------------|
| **7d** | Сьогодні + попередні 6 днів | 21 травня → 27 травня |
| **30d** | Сьогодні + попередні 29 днів | 28 квітня → 27 травня |
| **90d** | Сьогодні + попередні 89 днів | 27 лютого → 27 травня |
| **MTD** | З 1-го числа поточного місяця | 1 травня → 27 травня |
| **QTD** | З початку поточного кварталу | 1 квітня → 27 травня |
| **YTD** | З 1 січня поточного року | 1 січня → 27 травня |
| **All** | Уся доступна історія | — |
| **Custom** | Власний діапазон | Ви вказуєте початок і кінець |

> **Важливо:** Дані зберігаються максимум **90 днів** для статистики кампаній і **180 днів** для загальної щоденної статистики. Пресет `All` покаже тільки те, що є в базі (не більше цих лімітів).

**Як фільтр застосовується:**
- Дата береться з поля `report_date` (для daily_stats) або `date` (для campaign_daily_stats)
- Умова: `початок_діапазону ≤ дата_запису ≤ кінець_діапазону` (включно обидва кінці)
- Ліди фільтруються по `created_at` (дата створення ліда)

## 3. Сторінка Analytics / Statistics

Адреси: `/manager/statistics` (менеджер) та `/admin/statistics` (адмін).

### 3.1 Фільтри сторінки

Сторінка має **чотири незалежних фільтри**, які можна комбінувати:

```
[Timeframe ▾] [Manager ▾] [Client ▾] [Campaign ▾]
     │              │           │           │
     │              │           │           └── фільтр по конкретній кампанії
     │              │           └── фільтр по конкретному клієнту
     │              └── фільтр по менеджеру (тільки для адміна)
     └── фільтр по часу
```

**Ієрархія фільтрів (cascading):**
- Вибір менеджера → звужує список доступних клієнтів
- Вибір клієнта → звужує список доступних кампаній
- Вибір кампанії → перемикає джерело статистики (детальніше в [розділі 11](#11-логіка-вибору-джерела-даних))

**Пошук у фільтрах:** Кожен дропдаун має поле пошуку для швидкого знаходження потрібного запису.

**Що відбувається, якщо нічого не вибрано:**
- Менеджер: немає — показуються дані всіх менеджерів (тільки для адміна)
- Клієнт: немає — показуються дані всіх клієнтів (в рамках ролі)
- Кампанія: немає — агрегуються всі кампанії вибраного клієнта / всіх клієнтів

---

### 3.2 Картки-підсумки (Summary cards)

Розташовані вгорі сторінки. Показують загальні числа за вибраний часовий діапазон і фільтри.

#### Sent (Відправлено)
**Що показує:** Загальна кількість листів, відправлених за вибраний period.

**Формула:**
```
Sent = сума (emails_sent або sent_count) по всіх рядках,
       що потрапляють у вибраний timeframe та фільтри
```

**Джерело даних:** `daily_stats.emails_sent` (якщо кампанія не вибрана) АБО `campaign_daily_stats.sent_count` (якщо вибрана конкретна кампанія або немає записів у daily_stats).

**Приклад:** Якщо вибрано Manager = "Ірина", timeframe = MTD, і за травень Ірина вела клієнтів A та B, які разом відправили 15,000 листів — картка покаже 15,000.

---

#### Replies (Відповіді)
**Що показує:** Загальна кількість відповідей на листи (всі типи: людські, OOO, негативні).

**Формула:**
```
Replies = сума (response_count або reply_count)
          по всіх рядках у фільтрі
```

**Джерело:** `daily_stats.response_count` або `campaign_daily_stats.reply_count`

---

#### Bounces (Відмови доставки)
**Що показує:** Листи, які не були доставлені (hard bounce або soft bounce).

**Формула:**
```
Bounces = сума (bounce_count)
```

---

#### Reply Rate (Відсоток відповідей)
**Що показує:** Яка частина відправлених листів отримала відповідь.

**Формула:**
```
Reply Rate = (Replies / Sent) × 100%
```

**Якщо Sent = 0** → показується "—" (не ділиться на нуль).

---

#### Bounce Rate (Відсоток відмов)
**Формула:**
```
Bounce Rate = (Bounces / Sent) × 100%
```

---

#### Leads (Ліди)
**Що показує:** Кількість лідів, **створених** за вибраний period.

**Фільтрується по:** `leads.created_at` потрапляє в timeframe; клієнти відповідають вибраному менеджеру/клієнту.

**Важливо:** Це кількість нових лідів за period, а не загальна кількість лідів клієнта.

---

#### Campaigns (Кампанії)
**Що показує:** Кількість унікальних кампаній, по яких є активність у вибраному period.

---

### 3.3 Графік Sent Volume

**Тип:** Лінійний графік (line chart).

**Вісь X:** Дні у вибраному часовому діапазоні.

**Вісь Y:** Кількість відправлених листів.

**Як рахується кожна точка:**
```
Для кожного дня D:
  Sent(D) = сума sent_count (або emails_sent)
             по всіх кампаніях / клієнтах у фільтрі
             WHERE date = D
```

**Що означає відсутня точка:** За цей день немає записів у базі (кампанії не відправляли нічого або дані ще не завантажені).

**Лінії на графіку:**
- Якщо вибрана одна кампанія → одна лінія
- Якщо вибраний клієнт → одна агрегована лінія по всіх його кампаніях
- Якщо нічого не вибрано → одна загальна лінія

---

### 3.4 Графік Replies & Bounces

**Тип:** Лінійний графік, дві лінії.

**Лінія Replies (зелена/синя):** `response_count` по днях — всі відповіді.

**Лінія Bounces (помаранчева):** `bounce_count` по днях.

**Розрахунок:** Аналогічно Sent Volume, але з іншими полями.

**Навіщо:** Дозволяє побачити паттерни — наприклад, якщо Bounces різко зростають, це сигнал про проблеми з доставкою (погані домени, спам-фільтри).

---

### 3.5 Графік Lead Qualification Mix

**Тип:** Кругова діаграма (pie chart) + деталізація по менеджерах.

**Що показує:** Розподіл лідів по стадіях кваліфікації за вибраний period.

**Стадії (кольори):**

| Стадія | Що означає | Колір |
|--------|-----------|-------|
| **MQL** (Marketing Qualified Lead) | Лід кваліфікований, готовий до продажу | Синій/фіолетовий |
| **preMQL** | Лід потенційно цікавий, але ще не повністю кваліфікований | Блакитний |
| **Unqualified** | Лід є, але кваліфікація не встановлена або відхилено | Сірий |

**Формула для кожного сегменту:**
```
MQL count = кількість лідів WHERE qualification = 'mql'
            AND created_at у вибраному timeframe
            AND клієнт відповідає фільтрам

preMQL count = кількість лідів WHERE qualification = 'premql'
               AND ті самі умови

Unqualified = всі інші ліди в тих самих умовах
```

---

### 3.6 Секція By Manager

Розташована під Lead Mix. Показує **розбивку по менеджерах**.

**Що в кожній картці менеджера:**

| Поле | Що означає |
|------|-----------|
| **Name** | Ім'я менеджера |
| **Leads** | Кількість лідів (MQL + preMQL + unqualified) по всіх клієнтах цього менеджера за period |
| **MQL** | Кількість лідів з `qualification = 'mql'` |
| **preMQL** | Кількість лідів з `qualification = 'premql'` |
| **Unqualified** | Всі інші ліди |
| **Sent** | Сума відправлених листів по клієнтах цього менеджера за period |
| **Replies** | Сума відповідей |
| **Reply Rate** | Replies / Sent × 100% |

**Як рахується "Leads" для менеджера:**
```
Manager Leads = кількість лідів WHERE
  lead.campaign.client.manager_id = цей менеджер
  AND lead.created_at у вибраному timeframe
  AND якщо вибраний клієнт → тільки його ліди
```

**Якщо вибраний конкретний менеджер у фільтрі:** показується тільки його картка.

---

### 3.7 Секція By Client

Показує індивідуальні картки для кожного клієнта.

**Що в картці:**

| Поле | Формула |
|------|---------|
| **Sent** | Сума `emails_sent` клієнта за period |
| **Replies** | Сума `response_count` клієнта за period |
| **Leads** | Кількість лідів клієнта, створених за period |
| **Reply Rate** | Replies / Sent × 100% |

**Сортування:** За кількістю відправлених листів (спадання).

---

### 3.8 Campaign Portfolio

Показується внизу сторінки. Групується по клієнтах.

**Що показується по кожній кампанії:**

| Поле | Що означає |
|------|-----------|
| **Campaign name** | Назва кампанії |
| **Database size** | `campaigns.database_size` — скільки проспектів у базі цієї кампанії |
| **Positive responses** | `sum(positive_count)` — відповіді, класифіковані n8n як позитивні |
| **Sent** | `sum(sent_count)` за period |
| **Reply Rate** | `reply_count / sent_count × 100%` |
| **Статус** | Активна / завершена |

## 4. Сторінка Clients

Адреси: `/manager/clients` та `/admin/clients`.

Це найбільш деталізована таблиця системи — "мегатаблиця" з кількома групами колонок.

### 4.1 Фільтри сторінки

#### Health filter (фільтр за здоров'ям)
```
[ All ] [ Critical ] [ Danger ] [ Warning ] [ Healthy ]
```
Фільтрує рядки по **кольоровому стану** клієнта (визначається правилами умов — Condition Rules). Поруч з кожною кнопкою показується кількість клієнтів у цій категорії.

| Стан | Що означає |
|------|-----------|
| **Critical** | Клієнт порушує критичне правило (червоний) |
| **Danger** | Є серйозні проблеми (темно-помаранчевий) |
| **Warning** | Є попередження (жовтий) |
| **Healthy** | Немає спрацьованих правил (зелений) |

#### Search / Status / Manager filters
- **Search** — пошук по імені клієнта
- **Status** — мультивибір: Active, Abo, Sales, On hold, Offboarding, Inactive
- **Manager** — вибір менеджера (тільки для адміна)

#### Скидання фільтрів
Кнопка "Clear filters" з'являється, коли активний хоч один фільтр.

---

### 4.2 Колонки таблиці — DoD (день до дня)

DoD = **Day over Day**. Показує дані по конкретних днях відносно сьогодні.

#### DoD Schedule (колонки: +2, +1, 0)
**Що показує:** Скільки листів **заплановано** до відправки в майбутні дні.

| Колонка | Що рахує | Джерело |
|---------|---------|---------|
| **+2** | Заплановано "сьогодні на 2 дні вперед" | `daily_stats.schedule_day_after` (значення, записане n8n сьогодні, для дня +2) |
| **+1** | Заплановано "сьогодні на завтра" | `daily_stats.schedule_tomorrow` |
| **0** | Заплановано "сьогодні на сьогодні" | `daily_stats.schedule_today` |

**Важливо:** Ці числа — **прогноз n8n** на момент запису. Вони показують, скільки листів планується відправити.

#### DoD Sent (колонки: 0, -1, -2, -3, -4)
**Що показує:** Скільки листів **фактично відправлено** за кожен із 5 останніх днів.

| Колонка | Який день |
|---------|----------|
| **0** | Сьогодні |
| **-1** | Вчора |
| **-2** | Позавчора |
| **-3** | 3 дні тому |
| **-4** | 4 дні тому |

**Формула для кожного дня:**
```
DoD Sent(-N) = сума(daily_stats.emails_sent)
               WHERE report_date = (сьогодні - N днів)
               AND client_id = цей клієнт
```

---

### 4.3 Колонки 3-DoD (3-денний роллінг)

3-DoD = **3-Day Rolling**. Рахує ліди за кожен із 5 останніх 3-денних вікон.

#### 3-DoD Total (колонки: 0, -1, -2, -3, -4)
**Що показує:** Скільки нових лідів (MQL + preMQL) з'явилося за 3 дні, що починаються від кожного дня.

| Колонка | Який 3-денний period |
|---------|---------------------|
| **0** | День 0 + День -1 + День -2 (включно) |
| **-1** | День -1 + День -2 + День -3 |
| **-2** | День -2 + День -3 + День -4 |
| ... | ... |

**Формула:**
```
3-DoD Total(bucket B) = кількість лідів WHERE
  qualification IN ('mql', 'premql')
  AND created_at IN [день B, день B-1, день B-2]
  AND client_id = цей клієнт
```

#### 3-DoD SQL (колонки: 0, -1, -2, -3, -4)
**Що показує:** Тільки MQL ліди (Sales Qualified Leads) за ті ж самі 3-денні вікна.

**Формула:**
```
3-DoD SQL(bucket B) = кількість лідів WHERE
  qualification = 'mql'
  AND created_at IN [день B, день B-1, день B-2]
  AND client_id = цей клієнт
```

---

### 4.4 Колонки WoW (тиждень до тижня)

WoW = **Week over Week**. Кожна колонка — повний тиждень (Пн–Нд).

#### Доступні WoW колонки (5 тижнів: 0, -1, -2, -3, -4)
- **WoW 0** = поточний тиждень (з понеділка цього тижня до сьогодні)
- **WoW -1** = минулий тиждень (Пн–Нд)
- **WoW -2** = позаминулий тиждень
- тощо

#### WoW Response Rate
**Формула:**
```
Response Rate = sum(response_count) / sum(emails_sent) × 100%
за всі дні вибраного тижня для цього клієнта
```

#### WoW Human Rate (Human Reply Rate)
**Формула:**
```
Human Rate = sum(human_replies_count) / sum(emails_sent) × 100%
```
`human_replies_count` — відповіді, класифіковані n8n як "реальна людина" (не OOO, не автовідповідь).

#### WoW Bounce Rate
**Формула:**
```
Bounce Rate = sum(bounce_count) / sum(emails_sent) × 100%
```

#### WoW OOO Rate (Out-of-Office Rate)
**Формула:**
```
OOO Rate = sum(ooo_count) / sum(emails_sent) × 100%
```
`ooo_count` — відповіді типу "я у відпустці/відсутній".

#### WoW Negative Rate
**Формула:**
```
Negative Rate = sum(negative_count) / sum(emails_sent) × 100%
```

#### WoW SQL
**Формула:**
```
WoW SQL = кількість лідів WHERE
  qualification = 'mql'
  AND created_at у вибраному тижні
  AND client_id = цей клієнт
```

> **Якщо emails_sent = 0 за тиждень** → Rate показується як "—" (ділення на нуль не виконується).

---

### 4.5 Колонки MoM (місяць до місяця)

MoM = **Month over Month**. Кожна колонка — повний календарний місяць.

| Колонка | Який місяць |
|---------|------------|
| **MoM 0** | Поточний місяць (з 1-го по сьогодні) |
| **MoM -1** | Минулий місяць (повний) |
| **MoM -2** | Позаминулий місяць |
| **MoM -3** | 3 місяці тому |
| **MoM -4** | 4 місяці тому |

#### MoM SQL
```
MoM SQL = кількість лідів WHERE
  qualification = 'mql'
  AND created_at у вибраному місяці
  AND client_id = цей клієнт
```

#### MoM Total Leads
```
MoM Total = кількість лідів (будь-яка кваліфікація)
            WHERE created_at у місяці
```

#### MoM Meetings
```
MoM Meetings = кількість лідів WHERE
  meeting_booked = true
  AND created_at у місяці
```

#### MoM Won
```
MoM Won = кількість лідів WHERE
  won = true
  AND created_at у місяці
```

### 4.6 Кольорове підсвічування рядків

Рядки та клітинки можуть підсвічуватись кольором на основі **Condition Rules** (правил умов), які налаштовує адміністратор у Settings.

**Рівні серйозності:**

| Колір | Рівень | Опис |
|-------|--------|------|
| 🔴 Червоний | **critical_over** | Критична ситуація, потребує негайної уваги |
| 🟠 Помаранчевий | **danger** | Серйозна проблема |
| 🟡 Жовтий | **warning** | Попередження |
| 🟢 Зелений | **good** | Все гаразд |
| 🔵 Синій | **info** | Інформаційне повідомлення |

**Health Score (Здоров'я клієнта):**
```
Починається з 100 балів.
Кожне спрацювання правила відраховує:
  critical_over: -60 балів
  danger:        -25 балів
  warning:        -8 балів
Мінімум: 0 балів (не буває від'ємним)
```

**Які колонки можуть підсвічуватись:**
- Рядок цілком (за правилами на рівні `row`)
- Конкретна клітинка DoD Sent або DoD Schedule (за правилами на рівні `cell`)
- Клітинки WoW, MoM, 3-DoD колонок

## 7. Клієнтський портал — Дашборд

Адреса: `/client/dashboard`

Клієнт бачить тільки свої дані. Усі метрики стосуються його кампаній типу `outreach`.

### 7.1 KPI-картки

П'ять карток у верхній частині:

#### MQL (Marketing Qualified Leads)
**Що показує:** Кількість лідів з `qualification = 'mql'` за вибраний period.

**Формула:**
```
MQL = кількість leads WHERE
  qualification = 'mql'
  AND created_at у timeframe
  AND campaign.client_id = цей клієнт
  AND campaign.type = 'outreach'
```

**Sparkline:** Міні-графік показує динаміку MQL по тижнях.

#### Meetings Booked
**Що показує:** Кількість лідів, для яких встановлено `meeting_booked = true` за period.

**Формула:**
```
Meetings = кількість leads WHERE
  meeting_booked = true
  AND created_at у timeframe
  AND (умови клієнта)
```

#### Deals Won
**Що показує:** Кількість лідів з `won = true` за period.

#### Emails Sent
**Що показує:** Загальна кількість відправлених листів за period.

**Формула:**
```
Sent = сума(campaign_daily_stats.sent_count) WHERE
  date у timeframe
  AND campaign.client_id = цей клієнт
  AND campaign.type = 'outreach'
```

#### Prospects (Проспекти)
**Що показує:** Загальна кількість проспектів у базах кампаній клієнта.

**Формула:**
```
Prospects = сума(campaigns.database_size) WHERE
  client_id = цей клієнт
  AND type = 'outreach'
```

АБО (якщо `database_size` не заповнено):
```
Prospects = clients.prospects_added
```

### 7.2 Графіки клієнта

#### Daily Sent (Щоденні відправки)
**Тип:** Area chart (заповнений лінійний).
**Що показує:** Кількість відправлених листів по днях.
**Джерело:** `campaign_daily_stats.sent_count` — агрегований по днях.

#### Weekly Leads (Тижневі ліди)
**Тип:** Bar chart (стовпчикова діаграма).
**Що показує:** Кількість нових лідів по тижнях.
**Стовпчики:** MQL (синій/фіолетовий) + preMQL (блакитний) — складені (stacked).

#### Monthly Leads (Місячні ліди)
**Тип:** Bar chart.
**Що показує:** Ліди по місяцях (MQL + preMQL, stacked).

#### Prospects Over Time
**Тип:** Лінійний.
**Що показує:** Зміна `prospects_count` (з `daily_stats`) по тижнях — скільки нових проспектів завантажується.

#### Sent by Month
**Тип:** Bar chart.
**Що показує:** Відправлені листи по місяцях.

#### Velocity (Швидкість конверсії)
**Тип:** Комбінований (bar + line).
**Що показує:** Відношення MQL до відправлених листів — показує, наскільки ефективно кампанії конвертують в ліди.

## 11. Логіка вибору джерела даних

Система використовує **два різних джерела** статистики. Вибір між ними відбувається автоматично:

```
Якщо вибрана конкретна кампанія (Campaign filter активний):
  → використовується campaign_daily_stats
  (детальніша статистика по конкретній кампанії)

Якщо кампанія НЕ вибрана:
  → спочатку перевіряється daily_stats
  → якщо рядків нема → fallback на campaign_daily_stats
  (агрегована статистика по клієнту)
```

**Різниця між джерелами:**

| | `daily_stats` | `campaign_daily_stats` |
|-|--------------|----------------------|
| Рівень | Клієнт (всі кампанії разом) | Окрема кампанія |
| Поле відправлено | `emails_sent` | `sent_count` |
| Поле відповідей | `response_count` | `reply_count` |
| Позитивні | Немає | `positive_count` |
| Вікно даних | 180 днів | 90 днів |

## 12. Обмеження вікна даних

Це технічне обмеження, про яке важливо знати:

| Таблиця | Максимальна глибина | Причина |
|---------|--------------------|---------| 
| `campaign_daily_stats` | **90 днів** | Обмеження часу запиту бази даних |
| `daily_stats` | **180 днів** | Те саме, але більше через агрегацію |
| `leads` | Залежить від ліміту завантаження | Завантажується повна історія в межах ліміту |

**Що це означає на практиці:**
- Якщо ви виберете пресет `All` або `YTD` на початку року — дані будуть тільки за останні 90/180 днів
- Пресет `90d` і `All` покажуть однакові дані для campaign_daily_stats
- Для статистики старше 90 днів потрібно дивитися в зовнішні системи (Smartlead, Bison)
